월 2.56억 토큰

PoC → 정식 서비스
최소 기능으로 가능성을 확인한 뒤 팀과 함께 고도화

구성원 누구나 업무에 맞는 LLM 모델을 선택하고, 대화와 생성 문서를 함께 활용할 수 있는 사내 환경을 만들고자 했습니다. LiteLLM을 활용한 최소 기능의 챗봇을 단독으로 설계·구현하고, 팀장님·본부장님 리뷰를 거쳐 팀과 함께 정식 서비스로 발전시켰습니다.

베타 파일럿에서 받은 마케터의 HTML 문서 공동 작업 요구는 아티팩트 협업 기능으로 확장했습니다. 현재는 전사 약 200명을 대상으로 약 100명이 실사용하고 있습니다.

기간 2025.07 – 2026.07 (약 1년) 초기 PoC FE·BE 단독 설계·구현 정식 개발 BE 개발자·기획자·디자이너와 협업하며 프론트엔드 전담 스택 Vue 3 · TypeScript · SSE · TipTap

1 시작 배경과 목표

사내 AI 활용을 확대하려면, 먼저 구성원 누구나 접근해 업무에 맞는 LLM 모델을 선택할 수 있는 공통 환경이 필요하다고 판단했습니다. 여러 제공사의 모델을 한곳에서 활용할 수 있는 사내 챗봇을 첫 단계로 삼았습니다.

이후에는 팀별 대화와 생성 문서 공유로 확장하고, 사내 활용 데이터를 바탕으로 필요한 기능을 발전시키고자 했습니다. 챗봇 하나를 만드는 데 그치지 않고, 구성원의 업무에 맞춰 계속 고도화할 수 있는 출발점을 마련하는 것이 목표였습니다.

2 맡은 역할

초기 PoC · 전체 설계와 FE·BE 단독 구현

LiteLLM을 활용해 최소 기능의 사내 챗봇을 설계하고, 프론트엔드와 백엔드를 연결한 전체 동작 흐름을 단독으로 구현했습니다.

정식 개발·고도화 · 4인 팀의 프론트엔드 전담

백엔드 개발자·기획자·디자이너와 협업하며 프론트엔드 전체를 담당했습니다. 베타 파일럿의 피드백을 반영해 기능을 확장했으며, 담당 범위는 다음과 같습니다.

  • 채팅과 파일 활용 멀티 LLM 모델 선택, 스트리밍 응답, 파일 입력·미리보기, 대화 기록 관리
  • 인증과 접근 제어 SSO 연동, 세션 관리, 사용자 권한에 따른 화면과 기능 접근 처리
  • 아티팩트 협업 생성·편집·공유, 버전 관리와 변경 비교, 편집 잠금, 변경 이력과 임시저장

3 핵심 판단과 설계

일정과 안정성을 고려한 편집 방식 선택

여러 사람이 동시에 문서를 수정하려면 변경 내용의 병합과 충돌 처리 등 설계·검증해야 할 범위가 커집니다. 당시 일정 안에서 협업 기능을 빠르게 제공하기 위해, 구현과 검증 범위를 관리할 수 있는 편집 잠금 방식을 선택했습니다.

폴링으로 편집 상태를 확인하고 한 번에 한 명만 수정하도록 구성해, 동시 변경을 병합하는 복잡도를 줄였습니다. 이를 통해 문서를 공유하고 편집하는 핵심 흐름을 안정적으로 제공하는 데 집중했습니다.

전사 서비스의 인증과 접근 제어 보완

외부 보안 감사에 대비해 챗봇의 로그인과 공유 기능에서 접근 조건을 점검했습니다. 공유 링크에서도 로그인을 필수화하고, 외부 IP 접속에는 추가 인증(MFA)을 적용했습니다.

리다이렉트 경로를 검증하고 새 창을 통한 인증 우회 경로를 차단했습니다. 또한 HttpOnly 쿠키 기반 인증에 맞춰 프론트엔드의 세션 처리를 정비하고, 중복된 토큰 갱신 요청을 하나로 묶어 처리하도록 개선했습니다.

메인 번들 분리와 용량 축소

프론트엔드 번들 구성을 점검하고, 라우터의 비동기 로딩과 아티팩트 컴포넌트·외부 라이브러리 코드 분리를 적용했습니다. 메인 번들을 2,376KB에서 455KB로 줄였으며, 앱 코드와 라이브러리 코드를 분리해 변경 범위에 따라 캐시를 활용할 수 있도록 구성했습니다.

4 해결 과정

PoC에서 협업 기능 고도화까지

  1. 약 1주 만에 최소 PoC 구현과 첫 리뷰
    LiteLLM을 활용해 최소 기능의 챗봇을 FE·BE 단독으로 구현하고, 약 1주 만에 팀장님 리뷰를 진행했습니다. 이후 본부장님 리뷰로 이어지며 정식 서비스로 발전시키는 방향을 확인했습니다.
  2. 4인 팀으로 정식 서비스 개발
    백엔드 개발자·기획자·디자이너와 함께 서비스를 구체화하고, 프론트엔드를 전담했습니다. 채팅·모델 선택·파일 입력·인증 등 구성원이 실제로 사용할 기능을 구현했습니다.
  3. 베타 피드백을 협업 기능으로 확장
    베타 파일럿의 피드백 채널을 통해 마케터의 HTML 문서 공동 작업 요구를 확인했습니다. 아티팩트 협업 PoC를 빠르게 구현한 뒤, 한 번에 한 명이 편집하는 방식으로 정식 기능을 고도화했습니다.

운영 중 개선 사례

생성 문서의 내용과 표시 형식 보완

LLM 응답을 화면에 표시하는 과정에서 불릿과 강조 표현이 깨지거나, 복잡한 표의 내용이 누락되는 문제를 확인했습니다. 불필요한 전처리는 제거하고, 마크다운 변환 과정에서 정보가 손실되는 표는 HTML로 유지하도록 처리 경로를 조정했습니다.

긴 문서의 PDF 다운로드 개선

긴 아티팩트를 PDF로 내려받을 때 빈 문서가 생성되는 문제를 확인했습니다. 문서 전체를 한 번에 이미지로 만드는 방식의 크기 제약을 확인하고, 문서를 여러 영역으로 나누어 캡처한 뒤 페이지 단위로 PDF를 구성하는 방식으로 변경했습니다.

7 배운 점

작동하는 PoC는 관계자와 서비스의 가능성을 판단하는 기준이 됐고, 베타 사용자의 피드백은 다음에 필요한 기능을 구체화하는 계기가 됐습니다. 아티팩트 협업에서도 당시 일정과 구현 복잡도를 고려해 검증 가능한 범위를 정했습니다. 초기 구현 이후에도 실제 사용에서 드러나는 요구와 제약에 맞춰 서비스의 범위와 구현 방식을 조정하는 과정이 중요하다는 점을 배웠습니다.
